## Краткое описание

Цель проекта - разработать ML-сервис для анализа customer journey в e-commerce и оценки вероятности завершения покупки.

Основной датасет - [**<u>RetailRocket</u>**](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset/data?select=events.csv) с событиями view, addtocart, transaction.

Для решения задачи планируется:

- представить customer journey как граф состояний и переходов;

- использовать **Markov Chain**, которую можно интерпретировать как Random Walk по графу состояний, для оценки вероятностей переходов и вероятности достижения Purchase;

- использовать **Logistic Regression** и **CatBoost** для оценки той же вероятности на основе более детальных behavioral features;

- дополнительно протестировать **GRU / sequence-based neural network** для проверки ценности порядка пользовательских событий. В финальное решение нейросетевая модель включается только при подтвержденной дополнительной ценности по сравнению с более простыми подходами.

# 1. Бизнес-анализ (Business Understanding)

# Пользователи сервиса

Проект выполняется в учебном формате без коммерческого заказчика.

Предполагаемые пользователи - **Product Analyst, Product Manager и Growth Manager** e-commerce. Сервис должен помогать им находить проблемные точки *customer journey*, выявлять сессии с повышенным риском незавершенной покупки и формировать продуктовые гипотезы.

# Бизнес-проблема и цель

Воронка view → addtocart → purchase показывает общий drop-off, но не объясняет, как конкретный путь пользователя связан с вероятностью завершения покупки.

Цель проекта - поддержать снижение cart abandonment за счёт более раннего выявления рискованных состояний и сессий.

В проекте используются взаимодополняющие подходы:

- **Markov Chain / Random Walk interpretation** моделирует customer journey и оценивает P(purchase) на основе текущего состояния и вероятностей дальнейших переходов;

- **Supervised ML** оценивает P(purchase) на основе более детальных behavioral features, доступных к моменту прогноза;

- **GRU** дополнительно проверяет, даёт ли сама последовательность пользовательских событий дополнительную predictive value.

Сравнение подходов должно показать, насколько более детальные признаки и последовательность событий улучшают прогноз относительно более простой journey-based probabilistic model.

По результатам анализа формируются продуктовые гипотезы (push, скидка, изменение интерфейса и другие). Экспериментальная проверка гипотез через A/B-тесты не входит в scope текущего проекта и рассматривается как возможный следующий этап.

# Существующие решения

На рынке существуют решения, решающие аналогичную задачу:

- **Amplitude;**

- **Google Analytics 4**;

- **Mixpanel** и другие продукты.

Коммерческие платформы предоставляют готовую функциональность для продуктовой аналитики и prediction.

Цель проекта - не воспроизвести коммерческие платформы целиком, а реализовать прозрачный и воспроизводимый подход к моделированию customer journey и сравнить journey-based probability с supervised ML и sequence-based model.

Доступные события:

- view;

Для core-проекта достаточно локального компьютера. Для GRU / deep learning экспериментов при необходимости может использоваться Google Colab с GPU.

# 1.2 Решаемые задачи с точки зрения аналитики (Data Mining Goals)

# Техническая постановка

**Prediction point:** первый addtocart в пользовательской сессии.

**Target:**

- purchase = 1 — после первого addtocart в той же сессии произошел transaction;

- purchase = 0 — покупка в этой сессии не произошла.

Для бизнес-интерпретации используется обратная вероятность: чем ниже P(purchase), тем выше abandonment risk. Таким образом, сессии с наименьшей прогнозируемой вероятностью покупки соответствуют сессиям с наибольшим риском незавершенной покупки:

**abandonment risk = 1 − P(purchase)**

Все подходы сравниваются на одном prediction point и одном target:

- Markov Chain оценивает вероятность покупки на основе состояния customer journey и transition probabilities;

- Logistic Regression и CatBoost - на основе behavioral features;

- GRU - на основе последовательности событий.

# Модели

Планируется сравнить:

1.  Simple baseline.

2.  Markov Chain / Random Walk.

3.  Logistic Regression.

4.  CatBoost.

5.  GRU - дополнительный эксперимент для проверки ценности последовательности событий; включается в финальное решение только при измеримом улучшении относительно более простых моделей.

## Simple baseline

В качестве основного simple baseline всем сессиям присваивается одинаковая вероятность покупки, равная purchase rate в обучающей выборке. Этот baseline используется как минимальная точка сравнения и как референс для критерия успешности модели.

Дополнительно будет сформирован **business-rule baseline** на основе 1-2 интерпретируемых поведенческих признаков, например времени до addtocart и числа просмотров. Направление зависимости и пороговые значения будут определены только по train data.

Если модель не превосходит основной simple baseline, её predictive value считается недостаточной.

# Метрики

Основная метрика - **PR-AUC**.

Дополнительно используются:

- **ROC-AUC** - способность модели разделять purchase / no purchase;

- **Lift@20%** - во сколько раз доля покупок в top-20% сессий по score выше, чем в среднем по всей выборке;

- **Recall@20%** - какую долю всех покупок удалось охватить в top-20% сессий с наибольшей прогнозируемой вероятностью покупки;

- **Brier Score** - насколько предсказанная вероятность близка к фактическому исходу 0/1; чем меньше значение, тем лучше вероятностный прогноз.

# Критерий успешности

Модель считается успешной, если на **temporal test**:

- **PR-AUC как минимум на 20% выше simple baseline**;

- **Brier Score ниже baseline**.

Другие метрики используются как дополнительные метрики сравнения.

# MVP / Definition of Done

Минимальная версия продукта должна:

- обрабатывать event data RetailRocket и формировать пользовательские сессии;

- моделировать customer journey и рассчитывать вероятности переходов между состояниями;

- оценивать P(purchase) и abandonment risk после первого addtocart;

- сравнивать journey-based probabilistic model (Markov Chain) с simple baseline и supervised ML;

- дополнительно оценить GRU и использовать её в финальном решении только при подтвержденной дополнительной ценности;

- показывать основные результаты и сессии / состояния с повышенным риском в Streamlit;

- формировать минимум 2-3 продуктовые гипотезы для дальнейшего A/B-тестирования.

MVP считается готовым, если pipeline воспроизводим, модели проверены на temporal test, выполнены заданные критерии качества, а пользователь может получить и интерпретировать результат через интерфейс сервиса.

# Итоговая формулировка

В рамках учебного проекта разрабатывается ML-сервис для моделирования пользовательского пути, оценки вероятности покупки и выявления состояний с повышенным риском незавершенной покупки, предназначенный для поддержки продуктовой аналитики и формирования гипотез для последующих экспериментов.
